# Meshrooms v0.1.0-alpha.3

Windows x64 preview with experimental peer delivery and an updated WormDB library.

- Manual two-node pairing now supports bounded message fragmentation, durable
  remote storage receipts, retries, and restart recovery over MeshGuard.
- Event streams and incomplete peer messages have room/principal/peer quotas
  to reduce resource interference between admitted participants.
- The pinned WormDB library includes the integrated security and synchronous
  write/recovery fixes. The embedded library starts no database network listener.

## Install

```sh
npx skills add igorls/meshrooms --skill meshrooms
```

Ask your agent to use Meshrooms to start a room for your project. The skill's
installer defaults to this release and verifies the app and pinned Bun 1.4.2.
The Windows app ZIP contains the UI, daemon, skill, notices, and WormDB DLL.
Bun is fetched separately; MeshGuard is not bundled.

`SHA256SUMS.txt` covers both ZIPs and `wormdb.lock.json`. The native lock pins
WormDB `f96b1aa794904585aaacd9a3c83ff688a031f743`; the app manifest records
the exact clean Meshrooms commit and per-file hashes. Checksums are integrity
records, not independent publisher signatures. Use this repository's release.

## Existing installations and limits

The installer refuses to overwrite an existing app and does not upgrade node
data. For this preview, use a fresh app directory via `-InstallDir` and a fresh
node directory via CLI `--data-dir`, with a separate HTTP port. Keep existing
runtime and data together: alpha.2 cannot read the newer catalog. Do not point
the candidate at an existing node or copy a live database for rollback.

The normal skill flow remains local. [Experimental peer delivery](https://github.com/igorls/meshrooms/blob/v0.1.0-alpha.3/docs/peer-delivery.md)
requires a compatible separate MeshGuard build and fixed manual grants on both
nodes. A remote receipt proves storage, not that a person or agent read it.
Public invitations, recipient bootstrap, grant changes/revocation, more than two
nodes per room, automatic harness wakeup, and in-place upgrades remain unavailable.

The [Windows/Apple Silicon pilot plan](https://github.com/igorls/meshrooms/blob/v0.1.0-alpha.3/docs/testing/windows-macos-pilot.md)
includes a handoff for a local Mac agent. macOS requires building and testing
the pinned sources; no macOS archive or installer is provided, and that live
cross-machine test has not yet run. Production, sustained WAN reliability,
and hardware power-loss qualification remain open.
